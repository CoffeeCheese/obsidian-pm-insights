# Project Manager Insights 0.5.5

[简体中文](./0.5.5.zh-CN.md)

Project Manager Insights 0.5.5 makes the personal delivery brief's capacity window match the stage interval it represents and clarifies the visual roles of its summary areas.

## Highlights

- Calculate each delivery checkpoint's available capacity from the previous configured stage gate to the current delivery gate. The personal brief no longer substitutes today's planning-range boundary for the start of that stage interval.
- Carry the resolved stage-window start through member commitments, delivery windows, and cumulative capacity checkpoints so every surface reports the same date range and workday count.
- Present the tightest interval in the masthead as an explicit **stage start → workdays → delivery gate** route.
- Keep the buffer or shortfall conclusion in the dedicated **Delivery capacity** card, removing the duplicate capacity result from the masthead while preserving the project-level checkpoint detail below.
- Refresh the English and Simplified Chinese README screenshots with fictional demo projects and members, and document the revised capacity semantics.

## Capacity-window rules

- The delivery date still comes from the farthest mapped delivery stage covered by the member's project work.
- Capacity now begins at the previous configured stage gate and ends at that resolved delivery gate.
- Earlier project commitments continue to consume capacity before later commitments in cumulative comparisons.
- The 7-, 14-, or 30-day planning range only controls which delivery windows appear; it does not redefine a stage window's start or change project workload membership.
- Missing estimates and unresolved stages remain visible as planning-confidence gaps instead of being converted into invented dates or hours.

## Verification

- TypeScript checking, Obsidian ESLint rules, official-review regression checks, automated tests, and the production build pass.
- Regression coverage includes a four-workday stage interval and verifies that delivery-window and capacity-card figures use the same boundary.
- The `dev-test` Vault was used to verify the installed plugin, bilingual personal-brief rendering, explicit stage routes, and the single capacity-comparison presentation with fictional data.
