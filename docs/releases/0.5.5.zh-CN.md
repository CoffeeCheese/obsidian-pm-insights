# Project Manager Insights 0.5.5

[English](./0.5.5.md)

Project Manager Insights 0.5.5 让个人交付简报中的容量窗口与实际表达的阶段区间保持一致，并重新明确顶部摘要与容量卡片各自承担的信息职责。

## 功能亮点

- 每个交付节点的可用容量改为从“上一个已配置阶段门禁”计算到“当前交付门禁”，不再错误地使用今天或规划范围起点作为阶段窗口起点。
- 将解析出的阶段窗口起点贯穿成员交付承诺、交付窗口与累计容量节点，确保各区域展示相同的日期范围和工作日数。
- 顶部把最紧区间明确呈现为**阶段起点 → 工作日数 → 交付节点**的可视路线。
- 余量或缺口结论只保留在独立的**交付容量对比**卡片中，移除顶部重复的容量结论，同时保留下方按项目展开的容量节点明细。
- 使用完全虚构的演示项目与成员重新生成中英文 README 截图，并同步说明修正后的容量统计口径。

## 容量窗口口径

- 交付日期仍由成员在该项目中覆盖的最远交付阶段决定。
- 容量窗口从上一个已配置阶段门禁开始，到解析出的当前交付门禁结束。
- 较早项目的承诺仍会先占用容量，再进入后续项目的累计对比。
- 7、14、30 天规划范围只控制时间轴展示哪些交付窗口，不会重新定义阶段窗口起点，也不会改变项目工作负载的任务范围。
- 未估时与阶段无法解析的工作继续作为计划置信缺口展示，不会被转换成虚构的日期或工时。

## 验证

- TypeScript 类型检查、Obsidian ESLint 规则、官方审核回归检查、自动化测试和生产构建通过。
- 回归测试覆盖四个工作日的阶段区间，并验证交付窗口与容量卡片使用相同的边界。
- 已在 `dev-test` Vault 验证安装后的插件、中英文个人简报、明确的阶段路线，以及使用虚构数据时只出现一次的容量对比。
