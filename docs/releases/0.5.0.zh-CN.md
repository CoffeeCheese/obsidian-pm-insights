# Project Manager Insights 0.5.0

[English](./0.5.0.md)

Project Manager Insights 0.5.0 将“交付门禁”从一组固定日期扩展为可追溯的延期计划流程。团队可以保留项目原计划，独立评估并确认新的交付路径，再由实际门禁进展自动结算剩余延期，全程不会改写 Project Manager 数据。

## 重点更新

### 原计划与延期计划相互隔离

- 原始门禁日期保持不变，延期评估、审核与确认在独立计划中完成。
- 同一时间只允许存在一份待确认评估。可以先保存评估，再直接从对应动态中确认；也可以跳过评估步骤，立即确认当前延期计划。
- 完整记录每次评估与调整，包括把“延期 10 天”缩短为“延期 5 天”等变化，以及对应的调整原因和时间。
- 延期事项撤销后直接在原记录中标注状态，不再额外生成一条高密度动态。
- 产生延期历史后锁定原始日期；如需修改原计划，必须先清理全部延期数据，但共享的项目时钟仍可调整。

### 延期天数联动与自动结算

- 既可以选择预计日期，也可以直接填写延期工作日或自然日，两种输入会实时双向换算。
- 通过紧凑的减号和加号按钮逐日调整延期，并自动顺延后续门禁。
- 门禁通过后按实际日期自动结算。例如预估延期 5 天、实际只延期 3 天时，系统会自动体现追回的 2 天，无需手动填写。
- 保留门禁通过、重新打开、日期校正与上线登记事件，让当前计划始终可以回溯。
- 未保存的本轮评估可以取消并返回上一份计划；存在编辑内容时会先确认是否放弃。

### 所有计算共用同一个项目时钟

- 每个项目可以选择周末继续推进，或仅按工作日计算。
- 计划应达、剩余时间、逾期时间、任务与门禁差值、延期天数及后续预计日期统一使用同一规则。
- 旧版排期继续保持原有自然日口径，只有用户主动开启后才切换为仅工作日。
- 即使原始日期已经锁定，周末规则仍可编辑；存在未保存的时钟变更时，界面会先说明影响再继续延期编辑。

### 更清晰的时间线与风险上下文

- 在原计划时间线的受影响节点旁展示轻量延期标记，不再挤占日期输入区域。
- 在交付门禁风险阶段行中直接展示原计划、延期与实际日期，并补充预计延期和剩余时间。
- 在项目摘要与风险摘要中提示延期状态，详细修订历史则继续收纳在延期计划页中。
- 优化大型门禁编辑器中的聚焦边框、按钮层级、响应式布局和减少动态效果支持。

### 修复与文档

- 中英文“进度落后”统一使用 `%`，不再展示内部含义不明确的 `pp` 缩写。
- 优化危险操作确认样式，并明确区分取消、保存评估、确认延期、撤销事项和清理数据。
- 在中英文 README 中加入 Project Manager 工作界面的静态概览图。

## 兼容性与升级说明

- 继续支持 Obsidian `1.7.2` 及以上版本。
- 仍然依赖 Project Manager。门禁排期、延期修订和实际门禁事件保存在 PM Insights 自身设置中，不会改写项目笔记、任务笔记或 Project Manager 元数据。
- 现有门禁排期会自动迁移，并继续保持之前的自然日计算方式。
- 已有 PM Insights 设置保持兼容，本次升级不包含破坏性数据变更。
- 插件 ID 仍为 `project-manager-insights`。
