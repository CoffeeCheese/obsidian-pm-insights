# Project Manager Insights 0.4.0

[简体中文](./0.4.0.zh-CN.md)

Project Manager Insights 0.4.0 makes delivery-gate risk easier to interpret and tune. It distinguishes early and parallel execution from real schedule slippage, turns the launch reminder into a project-level closing signal, and shows the reason behind every task-level warning.

## Highlights

### More truthful stage-progress signals

- Distinguish work that starts **ahead of its planned window** from work that moves **across stages while an earlier gate remains incomplete**.
- Keep completed-stage timing as the primary signal after work passes a gate, instead of leaving it labeled as parallel progress.
- Compare actual and expected progress with the stage's own natural-day window so normal parallel delivery is visible without being treated as failure.

### A project-level launch reminder

- Assess the launch reminder across the complete project timeline and all configured stages instead of depending on one preceding gate.
- Keep acceptance progress as the final delivery standard; the launch date remains a schedule reminder rather than a second completion rule.
- Replace the repeated launch task list with a compact project handoff summary covering passed gates, risk gates, open work, and acceptance blockers.

### Risk reasons attached to the task that caused them

- Show direct reason chips for task overdue, planned after gate, missing due date, missing estimate, unassigned work, acceptance blockers, incomplete acceptance, schedule gap, and closing gate windows.
- Keep risk labels compact and separated from task-row dividers for easier scanning.
- Use neutral header colors when a gate timeline is healthy and reserve warning colors for real attention states.

### Due-date checks under user control

- Turn task due-date checks on or off from either plugin settings or the delivery-gate risk dialog.
- When disabled, missing due dates, overdue tasks, and tasks planned after a gate no longer affect risk.
- Gate dates, expected progress, stage gaps, and acceptance blockers continue to be checked independently.

### Better requirement and estimate semantics

- Treat root tasks as requirements rather than duplicate execution work, so they are not required to carry their own estimate.
- Continue to flag missing estimates on the delivery subtasks that represent actual work.
- Keep acceptance blockers distinct from requirement-level estimate signals.

### Documentation refresh

- Rebuilt the English and Simplified Chinese READMEs around Project Manager data enhancement, task-tree logic, delivery progress, gate risk, and source-task traceability.
- Added isolated fictional datasets and matching screenshots for delivery settings, progress, exceptions, gate schedules, risk details, dashboard summaries, and Project Manager task details.

## Compatibility and upgrade notes

- Obsidian `1.7.2` or later remains supported.
- Project Manager remains required, and Project Manager Insights remains read-only.
- Existing settings are migrated automatically. Task due-date checks stay enabled unless the user turns them off.
- No project notes, task notes, Project Manager metadata, or configured gate schedules are rewritten by this upgrade.
- The plugin ID remains `project-manager-insights`.
