# Project Manager Insights 0.4.0

[English](./0.4.0.md)

Project Manager Insights 0.4.0 进一步完善了交付门禁风险的判断与表达：区分提前推进、跨阶段推进和真实排期落后；将上线提醒调整为项目级收口信号；并让每条风险任务直接展示具体原因。

## 重点更新

### 更准确的阶段推进信号

- 区分在计划窗口前启动的**提前推进**，以及前一门禁尚未完成时后续阶段已经开展的**跨阶段推进**。
- 阶段通过后以实际通过时间作为主要信号，不再继续显示为跨阶段推进。
- 按各阶段自己的自然日窗口对比实际进度与计划应达，让并行交付能够被看见，而不会被简单判断为异常。

### 面向整个项目的上线提醒

- 上线提醒基于完整项目周期和所有配置阶段计算，不再依赖某一个前置门禁。
- 最终交付标准仍以验收进度为准；上线日期只承担项目节奏提醒，不形成第二套完成规则。
- 用精简的项目收口概览替代重复任务列表，集中展示已通过门禁、风险节点、待处理任务与验收阻塞。

### 风险原因直接关联具体任务

- 为任务展示“任务逾期”“晚于门禁”“未设截止日”“子任务未估时”“未分配”“阻塞验收”“验收未完成”“阶段进度落后”和“门禁临近”等直接原因。
- 风险标签采用更紧凑的布局，与任务分割线保持清晰间距。
- 门禁正常时使用中性色，仅在真正需要关注时显示警告色。

### 截止时间检测交给用户控制

- 可以从插件设置或门禁风险详情浮窗直接开启、关闭任务截止时间检测。
- 关闭后，未设置截止日、任务逾期和计划晚于门禁不再影响风险判断。
- 门禁日期、计划应达、阶段差距和验收阻塞仍会独立参与检测。

### 更符合需求模型的估时规则

- 主任务代表需求，不再要求主任务自身重复填写执行估时。
- 实际执行工作的交付子任务缺少估时时，仍然会作为风险和数据质量问题展示。
- 验收阻塞与需求层级的估时信号保持独立。

### 文档更新

- 重新梳理中英文 README，完整说明 Project Manager 数据增强、任务树设计、交付进度、门禁风险和源任务追溯。
- 使用隔离的虚构测试数据补充交付设置、交付进度、交付异常、门禁设置、风险详情、主面板汇总和 Project Manager 任务详情截图。

## 兼容性与升级说明

- 继续支持 Obsidian `1.7.2` 及以上版本。
- 仍然依赖 Project Manager，且 Project Manager Insights 保持只读分析。
- 现有设置会自动迁移；除非用户主动关闭，否则任务截止时间检测默认保持开启。
- 本次升级不会改写项目笔记、任务笔记、Project Manager 元数据或已经配置的门禁排期。
- 插件 ID 仍为 `project-manager-insights`。
