# Project Manager Insights 0.6.0

[简体中文](./0.6.0.zh-CN.md)

Project Manager Insights 0.6.0 adds explicit project launch confirmation, a traceable launch history, and consistent form controls across themes.

## Highlights

- Open a dedicated launch panel from the compact **Not launched / Awaiting launch confirmation / Launched** status beside each selected project, or from the launch node in gate risk details.
- Confirm the actual launch date after acceptance and prerequisite gates pass. A successful save shows a one-time launch animation and compares the actual date with the baseline and confirmed forecast.
- Correct a launch date or revoke a launch mark using the two always-visible actions below the result. Both require a reason and preserve the history timeline.
- Keep launched delay plans read-only. Revocation restores the previous delay state; reopened tasks remain visible without erasing the launch fact.
- Serialize settings writes and publish state only after a successful save, avoiding inconsistent results after failed or overlapping writes.
- Prevent Pixel theme borders, focus outlines, and Obsidian focus shadows from stacking. Dates, text fields, numbers, dropdowns, and composite fields share scoped, thin borders and a single focus indicator.
- Add English and Simplified Chinese screenshots of the launch status and history panel to the READMEs.

## Upgrade notes

Launch confirmation records a verified deployment; it does not deploy software, archive projects, or change task notes. Every project now requires explicit launch confirmation, including those without delay history. Existing valid launch dates remain recognized; projects previously treated as launched solely because acceptance passed now await confirmation.

When legacy records cannot establish the previous delay state safely, the plugin preserves the current launch record and explains what is missing. No minimum Obsidian version change is required.

## Verification

- TypeScript, Obsidian ESLint, official-review checks, all 194 automated tests, and the production build pass.
- 348 installed-style checks cover Pixel and the default theme, normal/focused/disabled controls, composite fields, and preservation of styles outside the plugin.
- Launch interactions were verified in the dev-test vault, including confirmation, correction, revocation, failed saves, and reopened tasks.
